## How the Code Works (plain language)

- **`shared/access-rules.ts`** is the rulebook. Each role has a list of resources, and each resource has one access level: change, read, request, decide, or none. The function `roleAllows` looks up the level and answers yes or no. It has no database and no network code, so it can be tested alone, and the frontend can use it later.
- **`server/access/membership.ts`** answers "is this person a member of this organization, and does their role allow this action?". Both the person and the organization must match. A membership in one organization never counts in another. This is the core of data isolation (ADR 0010).
- **`server/db/schema.ts`** describes the tables to Drizzle. Drizzle turns this description into SQL (migration file). The SQL creates the tables; no code runs against the database yet.
- **`server/auth/auth.ts`** configures better-auth, the login library. It stores accounts and sessions in our tables through the Drizzle adapter (a small connector). Passwords are stored only as hashes, by the library.
- **`server/auth/auth-routes.ts`** is a list of the only login addresses the internet may reach in Phase 1: sign-in, sign-out and reading the session. The other addresses (for example, sign-up) return 404.
- **`server/me/me.controller.ts`** answers `GET /api/me`. It reads the session cookie, finds the account, and returns that account's memberships. The query filters by the account, so one person never receives another person's memberships.
- **`server/db/seed-data.ts`** defines the fixed content loaded in Phase 1: MONUMENT, four roles, the permission rows, four fictional accounts (`*@expathio.test`), and one membership for each.
- **`server/db/seed.ts`** writes that content to the database. It is safe to run twice.
- **`server/config/config.ts`** reads the settings from environment variables and refuses to start if a required value is missing.
- **`server/main.ts`** joins the parts: settings, database, login, routes, HTTP server.

# 0007 — Participant Rules in the First Version

**Status:** APPROVED  
**Date:** 2026-11-03  
**Approved by:** Project owner

---

## Context

`01-PRODUCT.md` (section 11) asked several questions about how participants occupy roles and interact with the organization. Each affects permissions, workflows and the Roadmap.

## Decisions

1. **One occupant per role.** Multiple participants do not share a role in the first version.
2. **Role changes after the first version.** Participants keep their role in the first version. Changes come later.
3. **Feedback through observable results.** No formal evaluation in the first version (see `07-PROGRESSION-AND-REWARDS.md`, section 7).
4. **Freedom to propose actions.** Participants may propose actions outside predefined tasks. A simulated manager approves a proposal before it affects the organization.
5. **Departure hands the role to the simulation.** When a participant leaves, the simulation takes over the role's activities until the next occupant.

## Rationale

Each rule keeps permissions and state simple for the first version. Proposal approval keeps the consequences of freedom within the organization's rules, which matches `04-AI-AGENTS.md` (section 9).

## Consequences

- `01-PRODUCT.md` section 11 records each answer.
- Role changes and shared roles need their own specification in a later phase.
